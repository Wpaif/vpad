# vpad

[![CI](https://github.com/Wpaif/vpad/actions/workflows/ci.yml/badge.svg)](https://github.com/Wpaif/vpad/actions/workflows/ci.yml)
[![라이선스: MIT](https://img.shields.io/badge/%EB%9D%BC%EC%9D%B4%EC%84%A0%EC%8A%A4-MIT-blue.svg)](LICENSE)

[Português](README.md) · [English](README.en.md) · [Español](README.es.md) · [中文](README.zh-CN.md) · [日本語](README.ja.md) · **한국어**

휴대폰을 PC의 가상 컨트롤러로 만들어 줍니다. iPhone에서 페이지(또는 홈 화면 앱)를 열면 터치가 로컬 네트워크로 전달되고,
PC의 Rust 서버가 **가상 게임패드 또는 키보드**(uinput, Linux)를 만들어 어떤 게임이나 프로그램에서도 실제 장치로 인식됩니다.

- **프로파일**: Xbox 360, DualShock 4, Switch Pro, 키보드.
- **멀티터치**, 가상 아날로그 스틱, 트리거, 방향 패드를 지원하며 가로 모드와 전체 화면으로 사용합니다.
- **지연 시간을 한눈에**: ping/pong 측정기가 있고, 휴대폰의 Wi-Fi가 "잠들면" 쓸 수 있는 짧은 ping 모드가 있습니다.
- **편집 가능한 버튼 레이아웃**: 버튼을 이동하고, 크기를 바꾸고, 숨기고, 하나씩 따로 풀어서 옮길 수 있습니다.
- **여섯 가지 언어**: 포르투갈어, 영어, 스페인어, 중국어(간체), 일본어, 한국어. 휴대폰의 언어에 따라 선택되며 패널에서 바꿀 수 있습니다.
- **로컬 네트워크에 맞는 보안**: 자체 인증 기관을 쓰는 HTTPS, 코드 페어링, PC에서의 승인.

> 현재 지원: **Linux**(Manjaro에서 테스트)와 **iPhone**(Safari / 홈 화면 앱).
> Windows는 지원하지 않습니다.

## 요구 사항

PC:

- `uinput` 모듈이 있고 `/dev/uinput`에 쓰기 권한이 있는 Linux.
- 서버를 빌드할 Rust(2024 에디션, 즉 1.85 이상).
- 페이지를 빌드할 Node.js와 npm(Vite + Svelte).

휴대폰:

- Safari를 쓸 수 있는 iPhone. PC와 휴대폰은 **같은 로컬 네트워크**에 있어야 합니다.

`uinput`을 사용하려면:

```sh
sudo modprobe uinput
# 내 사용자에게 권한 주기(ACL 사용 예):
sudo setfacl -m u:$USER:rw /dev/uinput
```

부팅할 때마다 모듈이 자동으로 로드되게 하려면 `/etc/modules-load.d/uinput.conf` 파일을 만들고 `uinput` 한 줄을 넣으세요.
PC를 재시작한 뒤에도 권한이 유지되게 하려면 ACL 권한(또는 udev 규칙)도 영구적으로 설정해야 합니다.

## 설치

### 미리 빌드된 바이너리(Linux x86_64 / aarch64)

사용만 할 거라면 [최신 릴리스](https://github.com/Wpaif/vpad/releases/latest)에서 패키지(`vpad-X.Y.Z-linux-x86_64.tar.gz`, 옆에 `.sha256`이 있습니다)를 내려받아 체크섬을 확인하고 압축을 풉니다. Rust나 Node는 필요 없지만 [요구 사항](#요구-사항)의 `uinput` 설정은 여전히 필요합니다. 패키지는 **x86_64**(Intel/AMD)와 **aarch64**(64비트 ARM, 64비트 시스템을 쓰는 Raspberry Pi 4/5 등) 두 가지가 있습니다. ARM에서는 이름의 `x86_64`를 `aarch64`로 바꿔서 사용하세요. 그다음 [처음 사용하기](#처음-사용하기)로 넘어가세요.

```sh
sha256sum -c vpad-X.Y.Z-linux-x86_64.tar.gz.sha256
tar xzf vpad-X.Y.Z-linux-x86_64.tar.gz
cd vpad-X.Y.Z-linux-x86_64
./vpad
```

### 소스에서 빌드

프로젝트를 내려받고 폴더로 이동합니다:

```sh
git clone https://github.com/Wpaif/vpad.git
# 또는 SSH로: git clone git@github.com:Wpaif/vpad.git
cd vpad
```

페이지는 **바이너리에 포함**됩니다(release 빌드에서. debug에서는 서버가 디스크의 `web/dist`를 읽습니다).
그래서 서버보다 먼저 페이지를 빌드해야 합니다:

```sh
cd web && npm install && npm run build && cd ..
cargo build --release
```

바이너리는 `target/release/vpad`에 만들어집니다. `web/`의 내용을 바꿨다면
`npm run build`와 `cargo build --release`를 다시 실행하세요.

## 처음 사용하기

1. PC에서 **서버를 시작**합니다:

   ```sh
   ./target/release/vpad
   ```

   터미널에 QR 코드, 컨트롤러 주소(`https://PC의IP:8443`), 인증 기관의 SHA-256 지문,
   인증서가 포함하는 IP가 표시됩니다.

2. **iPhone에 인증서를 설치**합니다(한 번만). 처음 실행할 때 서버가 자체 인증 기관을 만들고
   HTTP(`http://PC의IP:8080`) 설정 페이지를 5분 동안 엽니다. 나중에 다시 열려면 터미널에 `c`를 입력하세요.
   iPhone에서는(페이지는 기기의 언어로 열리고 위쪽에 언어를 바꾸는 링크가 있습니다. 아래 iOS 메뉴 이름은 한국어 iOS의 이름입니다):

   1. 설정 페이지를 열고 **프로파일 다운로드** → **허용**을 탭합니다.
   2. **설정 → 프로파일이 다운로드됨**을 열고 인증서를 탭하여 세부 정보를 확인한 뒤, **SHA-256 지문**이
      **PC 터미널**에 표시된 것과 같은지 확인합니다. 그런 다음에만 **설치**를 탭합니다.
   3. **설정 → 일반 → 정보 → 인증서 신뢰 설정**에서 **vpad**에 대한 신뢰를 켭니다.

3. **기기를 페어링**합니다. 페어링은 기본적으로 **닫혀** 있습니다. PC 터미널에서 **Enter**를 누르면
   2분 동안 페어링이 열리고 30초마다 바뀌는 6자리 코드가 표시됩니다. iPhone에서 `https://PC의IP:8443`을 열고 코드를 입력하세요.
   PC가 승인을 요청합니다. **`y`**(또는 **`s`**)는 승인, **`k`**(또는 **`t`**)는 승인하면서 [키보드 모드](#키보드-모드)도 허용,
   다른 키는 거부입니다.

4. **앱으로 설치**합니다(선택, 권장): Safari에서 **공유 → 홈 화면에 추가**를 탭합니다.
   앱은 전체 화면 가로 모드로 열립니다.

> 홈 화면 앱은 Safari와 **별도의 저장 공간**을 쓰므로 따로 페어링해야 합니다.
> 앱을 다시 설치하면 다시 페어링해야 합니다. 버튼 레이아웃은 PC에도 저장되어 있어서 저절로 돌아옵니다.

## 일상적인 사용

서버가 실행 중이면 iPhone에서 앱을 엽니다. Wi-Fi가 끊어지면 저절로 다시 연결됩니다.

- **상태 알약**(위쪽): 지연 시간을 보여 줍니다. 탭하면 패널이 열리고, 프로파일 선택, 통계(최근, 평균, 최소,
  최대, 지터, 손실), 짧은 ping 버튼, 레이아웃 편집기로 가는 길이 있습니다.
- **눈 아이콘**(위쪽): 컨트롤을 숨기거나 보여 줍니다.
- **언어**: 패널에 여섯 가지 언어를 고르는 선택기가 있습니다. 처음 열 때는 휴대폰의 언어가 쓰입니다(번역이 없는 언어는 영어).
  바꾸면 페이지가 다시 로드됩니다.
- **짧은 ping**: 터치하지 않을 때 지연 시간이 올라간다면 iPhone의 Wi-Fi가 절전 상태에 들어갔기 때문입니다.
  *짧은 ping*을 켜면 100 ms마다 신호를 보내 무선을 깨어 있게 합니다(휴대폰 배터리를 더 씁니다).

서버 터미널의 명령(입력하고 Enter):

| 명령 | 동작 |
| --- | --- |
| `Enter` | 페어링을 2분 동안 열고 코드를 표시 |
| `f` 또는 `close` | 페어링을 바로 닫음 |
| `c` | 인증서를 설치하는 페이지를 5분 동안 엶 |
| `?` | 도움말 |
| `s` 또는 `y` / `t` 또는 `k` / 그 외 | 승인 요청에 답함: 예 / 예 + 키보드 허용 / 거부 |

## 명령줄 옵션

```
vpad [--perfil <xbox360|ds4|switch-pro|teclado>] [--porta <1-65535>]
     [--porta-https <1-65535>] [--parear]
vpad --dispositivos
vpad --revogar <id|todos>
vpad --permitir-teclado <id> | --negar-teclado <id>
```

옵션 이름은 포르투갈어이며 모든 언어에서 같습니다.

| 옵션 | 의미 |
| --- | --- |
| `--perfil` | 처음 프로파일(휴대폰에서 나중에 바꿀 수 있음). 기본값: `xbox360` |
| `--porta` | 인증서 설정 페이지의 HTTP 포트. 기본값: `8080` |
| `--porta-https` | 컨트롤러의 HTTPS 포트. 기본값: `8443` |
| `--parear` | 시작할 때 페어링을 엶(서버를 터미널 없이 실행할 때 유용) |
| `--dispositivos` | 페어링된 기기를 나열(id, 이름, 유효 기간, 마지막 사용, 키보드) |
| `--revogar` | id로 기기 하나, 또는 전부(`todos` 또는 `all`)를 폐기. 서버가 실행 중이어도 즉시 적용됨 |
| `--permitir-teclado` / `--negar-teclado` | 기기의 키보드 모드를 허용하거나 차단 |

## 버튼 레이아웃

상태 알약을 탭한 다음 **레이아웃 편집…**을 탭합니다. 패널이 닫히고, 그룹에 윤곽선이 생기며,
화면 가운데에 막대가 나타납니다.

- **이동**: 그룹을 끕니다. 화면 밖으로 나가지 않고, iPhone의 안전 영역을 지키며,
  다른 그룹의 가장자리와 중심에 (안내선과 함께) 붙습니다.
- **크기 조절**: 오른쪽 아래의 둥근 핸들을 끕니다. 배율은 0.5×에서 2×까지이고, 그룹은 가장자리를 넘어 커지지 않으며,
  가장 작은 버튼도 44 px 아래로 내려가지 않습니다.
- **숨기기**: **버튼** 버튼을 누르면 컨트롤마다 스위치가 하나씩 있는 목록이 열립니다. 이름은 사용 중인 프로파일을 따릅니다
  (DualShock에서는 엑스, 동그라미 등. 키보드 모드에서는 키).
- **그룹 잠금 해제**: 각 그룹(버튼이 둘 이상인 그룹)의 오른쪽 위 자물쇠로 그룹의 잠금을 풀면 버튼을 하나씩 따로 옮길 수 있습니다.
  잠긴 그룹은 한 덩어리로 움직입니다.
- **불투명도**: 막대의 슬라이더로 모든 버튼을 100%에서 20%까지 투명하게 만들 수 있습니다. 눌린 버튼은 완전히 보이므로
  불투명도가 낮아도 터치를 확인할 수 있습니다.
- **초기화 / 취소 / 저장**: **저장**만 기록합니다. **초기화**는 기본 레이아웃으로 되돌리고(초안 안에서), **취소**는 한 작업을 버립니다.

편집하는 동안 터치는 PC로 **전달되지 않습니다**. 레이아웃은 기기와 PC(`layout.json`)에 모두 저장되고 페어링된 기기끼리 공유됩니다.
앱을 다시 설치해도, Safari와 홈 화면 앱이 달라도 유지됩니다. PC와 연결되지 않으면 레이아웃은 기기에만 남고 나중에 전송되며,
패널에서 현재 상태를 볼 수 있습니다.

## 키보드 모드

**키보드** 프로파일에서는 버튼이 PC에 글자를 입력합니다. 강력한 기능이라서 두 가지 잠금이 있습니다:

1. 기기에 **키보드 권한**이 있어야 합니다. 페어링을 승인할 때(`k`) 주거나, 나중에 `vpad --permitir-teclado <id>`로 줍니다.
2. 모드를 켤 때마다 **PC가 터미널에서 확인을 요청**합니다.

패널의 **키 편집…** 버튼으로 각 버튼에 할당할 키를 고릅니다. 할당은 `teclado.json`에 저장됩니다.

## 보안

vpad는 가정의 로컬 네트워크를 위해 만들어졌지만 네트워크를 신뢰할 수 없는 것으로 취급합니다:

- **자체 인증 기관을 쓰는 HTTPS.** 인증 기관(CA)은 PC에서 만들어지며 로컬 네트워크의 이름과 IP에서만 유효합니다(이름 제약).
  키는 PC 밖으로 나가지 않습니다. SHA-256 지문이 터미널에 표시되므로 프로파일을 설치하기 전에 확인할 수 있습니다.
- **페어링은 기본적으로 닫혀 있습니다.** 코드는 6자리이고 30초마다 바뀝니다. 연속으로 틀리면 잠금이 점점 길어지고
  (60초, 300초, 1800초) 터미널에 IP가 포함된 경고가 나옵니다. 코드가 맞더라도 **PC 앞에 있는 사람이 승인**해야 합니다.
- **기기마다 토큰 하나.** 서버는 SHA-256 해시만 저장합니다. 토큰은 90일 동안 유효하고 기기마다 다른 기기에 영향 없이 폐기할 수 있습니다.
- **URL에 토큰이 없습니다.** WebSocket은 토큰을 서브프로토콜로, API는 `Authorization` 헤더로 받습니다.
- **서버 쪽 방어.** `Host`와 `Origin`을 확인하고(*DNS rebinding*과 외부 페이지 방지), 메시지와 본문의 크기를 제한하고,
  보안 헤더(엄격한 CSP, `X-Frame-Options`, HSTS 등)를 보냅니다. 휴대폰에서 6초 동안 신호가 없으면
  (1초에 한 번 ping을 보냅니다) 연결이 닫히고 모든 버튼이 해제됩니다.
- **키보드는 권한과 확인이 필요**합니다(위 참조).

의존성은 `make audit`이 RustSec 취약점 데이터베이스에서 확인합니다.

## 설정 파일

모든 것은 `$XDG_CONFIG_HOME/vpad/`(또는 `~/.config/vpad/`)에 있습니다:

| 파일 | 내용 |
| --- | --- |
| `dispositivos.json` | 페어링된 기기(id, 이름, 토큰의 **해시**, 유효 기간, 키보드 권한) |
| `dispositivos.vistos.json` | 각 기기의 마지막 사용 |
| `teclado.json` | 키보드 모드의 키 할당 |
| `layout.json` | 버튼 레이아웃. 페어링된 기기끼리 공유됨 |
| `tls/` | 인증 기관과 서버 인증서(`ca-chave.pem`은 CA의 키입니다: **공유하지 마세요**) |

처음부터 다시 시작하려면 `vpad` 폴더를 지우세요(프로파일을 다시 설치하고 다시 페어링해야 합니다).

## 개발

```sh
make test      # cargo test + npm test + 훅 테스트
make hooks     # master에 직접 커밋하는 것을 막는 훅을 설치
```

이 절은 요약일 뿐입니다. 프로젝트 구조, 바이너리 프로토콜, 번역 방식, 기여 절차 전체는
[포르투갈어 README](README.md)에 있습니다. 요약하면 기능마다 브랜치 하나, 테스트를 먼저 작성하고,
`master`는 CI를 통과한 pull request(`git push -u origin feature/<이름>`, `gh pr create --fill`, `gh pr merge --merge`)로만 변경을 받습니다.

## 자주 겪는 문제

| 증상 | 해결 방법 |
| --- | --- |
| `could not create the virtual controller` | 모듈을 로드하고(`sudo modprobe uinput`) 내 사용자에게 `/dev/uinput` 쓰기 권한을 줍니다 |
| Safari가 연결이 안전하지 않다고 경고함 | 인증서 프로파일이 설치되지 않았거나 *인증서 신뢰 설정*에서 신뢰를 켜지 않았습니다 |
| PC의 IP가 바뀐 뒤 인증서가 동작하지 않음 | 서버는 시작할 때 인증서를 스스로 갱신합니다. CA가 바뀌었다면 프로파일을 다시 설치하세요 |
| "페어링이 닫혀 있습니다" | PC 터미널에서 Enter를 눌러 2분 동안 엽니다 |
| "잘못된 시도가 너무 많습니다" | 잠금이 끝날 때까지 기다립니다(시간은 메시지에 표시됩니다) |
| 잠시 쉬었다가 처음 누른 키가 늦게 도착함 | 패널에서 **짧은 ping**을 켭니다. 휴대폰의 Wi-Fi가 잠들어서입니다 |
| 홈 화면 앱이 다시 페어링을 요청함 | Safari와 저장 공간이 분리되어 있으니 앱 안에서 한 번 페어링하세요 |
| 홈 화면에 예전 아이콘이 남아 있음 | iOS는 추가할 때 아이콘을 고정합니다. 앱을 삭제하고 다시 추가하세요 |
